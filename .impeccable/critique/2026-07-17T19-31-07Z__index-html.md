#### Anti-Patterns Verdict

**LLM assessment**: This does not read as generic AI slop. The split ledger layout, GT America Expanded display, full-row inversions, and grayscale-to-color imagery are committed choices with a named system ("Documentarian Ledger"). The site passes the first-order category reflex (not navy-and-gold fintech, not dark observability).

It does flirt with the **second-order editorial-typographic lane** (mono labels, ruled separators, coordinate metadata, uppercase section kickers). That lane is intentional here and matches PRODUCT.md, but a saturated 2026 recruiter has seen this family before. Differentiation now depends on case study depth and imagery, not the shell.

One shared-ban proximity: case study **stats blocks** (`stats__num` + `stats__label`) echo the hero-metric template. The copy is specific enough to avoid SaaS cliché, but the component shape is familiar.

**Deterministic scan**: CLI detector unavailable (`detect.mjs` exited: bundled detector not found). Manual source review found no gradient text, glassmorphism, box-shadow, or side-stripe accent borders. Structural `border-left` on `.stats` columns is a divider, not a card accent stripe.

**Visual overlays**: Not available. Live-server serves variant-mode APIs only (static `index.html` returned 404). No `detect.js` bundle in repo. Browser review used Playwright against a local static server instead.

#### Overall Impression

The portfolio shell is confident and on-brand: it looks designed, not templated. The biggest gap is **recruiter throughput**, especially on mobile and touch devices. The interface optimizes for editorial presence first and proof-of-work second. For hiring managers scanning four candidates in ten minutes, the path to "show me the dashboards" is longer than it needs to be.

#### What's Working

1. **Index row inversions** — Full-row hover/focus inversion with accent ID numbers is tactile, memorable, and matches the brutalist brief. It demonstrates interaction craft on the portfolio itself.
2. **Split panel as persistent identity** — Sticky dark panel with facts table on case pages gives hiring managers client/role/scope/year without hunting. Strong information scent.
3. **Progressive enhancement** — Reveal animations respect `prefers-reduced-motion`; no-JS users see everything. Aligns with the "resilient static build" principle.

#### Priority Issues

**[P1] Touch devices never see full-color imagery**
- **Why it matters**: Site cards and case figures rely on `:hover` to remove `grayscale(100%)`. On phones and tablets, shipped work and case screenshots stay gray, undermining the proof-of-craft goal for a large share of traffic.
- **Fix**: Add `@media (hover: hover)` so grayscale is default only where hover exists; show full color by default on `(hover: none)`.
- **Suggested command**: `adapt index.html and case study pages`

**[P1] Mobile scan path buries work below a tall hero**
- **Why it matters**: Below 768px the black panel consumes ~60vh before the case index appears. A hiring manager on a phone sees name and positioning copy, not project thumbnails or domain labels.
- **Fix**: Shorten mobile panel (`min-height`, tighter type scale), or surface a compact "01–04" index strip immediately after the name block.
- **Suggested command**: `layout index.html mobile panel and index`

**[P2] Domain context disappears on tablet/mobile index**
- **Why it matters**: `.index__kind` hides at `max-width: 1024px`, removing "Farm management", "Patient journeys", etc. Recruiters filtering by domain lose the fastest signal.
- **Fix**: Keep kind visible on mobile (wrap to second line, or show abbreviated domain under title).
- **Suggested command**: `adapt index.html index rows`

**[P2] Decorative "Sort: Selected" implies broken functionality**
- **Why it matters**: Reads like a filter control. Users may try to click it or wonder why sorting cannot change. Adds extraneous load without payoff.
- **Fix**: Remove it, or replace with a functional sort (year, domain) if the archive metaphor needs it.
- **Suggested command**: `distill index.html archive header`

**[P2] Stats blocks on case pages mirror the hero-metric anti-pattern**
- **Why it matters**: Large accent numbers with supporting labels (`100%`, `Bank-ready`, `3-up`) reuse a SaaS landing shape the brand explicitly rejects, even if copy is better.
- **Fix**: Reframe as pull quotes, inline proof sentences, or figure captions; drop the two-column metric grid.
- **Suggested command**: `distill work/*.html stats sections`

#### Persona Red Flags

**Alex (Power User / fast-scanning recruiter)**: No resume PDF link. Must scroll past hero on mobile to reach case index. External site cards open in new tabs but case studies require sequential scroll through index. High risk of bouncing before opening a case.

**Jordan (First-Timer)**: "Sort: Selected" looks clickable but is not. Nav anchor links jump sections but provide no active-state feedback after landing. Kardion caption says only "Site design" with no context for what that means.

**Dana (Design Hiring Manager — project-specific)**: Wants enterprise dashboard proof in under 30 seconds. Index rows are text-only (no hero thumbnail per case). Domain labels vanish on tablet. Stats blocks feel like marketing filler rather than evidence. The strongest work (Conservis map dashboard, Vidscrip timeline) requires clicking through.

**Sam (Accessibility-Dependent)**: Index rows use inversion for `:focus-visible` (good), but `outline: none` means keyboard users depend entirely on the inversion being noticeable. Nav links in `.archive__header` rely on browser default focus ring only (no custom `:focus-visible` styling). Profile section has two `h2` elements (`profile-title` section head and `profile__title`), muddying heading hierarchy for screen readers.

#### Minor Observations

- Inline styles on nav (`display:flex`) and contact margin should live in CSS for consistency.
- Accent red (`#fa1900`) is underused outside ID numbers and external-link arrows; coordinate/VOL labels could carry one accent hit without breaking the ≤10% rule.
- Case study `.article__head` max-width of 22ch can produce awkward wraps on mid-width viewports.
- `visually-hidden` uses deprecated `clip: rect()`; prefer modern `clip-path: inset(50%)` pattern.
